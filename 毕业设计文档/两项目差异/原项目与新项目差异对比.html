四、被移除或降级的部分

原项目中以下能力在新项目里不是核心，可移除或延后：

Git 仓库克隆、代码索引、code_agent 作为主场景；

Coding Agent 的 Sandbox、Diff、测试执行、PR 生成（M2 原核心，新项目不需要）；

博客路径配置和博客接入；

爬虫深度抓取、去重调度（新项目可先只做网页搜索/上传文档）；

MCP、工具市场、多租户等平台化能力（延后到 M4 或不做）。

注意：移除不等于删除代码，建议保留原项目代码作为技术资产；新项目可复制平台层，替换 Agent 与场景层。

八、复用与改造建议

建议新项目不要从零开始，而是复制原项目并分层替换：

第一步：复制 Java 平台骨架、Vue 基础、FastAPI 基础、Docker Compose；

第二步：保留 Task/Trace/SSE/消息体系，新增 user/document/agent_run/shared_memory；

第三步：重写 Python Agent Runtime，把单 Agent 替换为 Coordinator + 专业 Agent；

第四步：重写前端场景入口与结果页，弱化技术术语；

第五步：先做学习规划、文档理解、报告生成三个 P0 场景，再扩展信息核查/生活决策/编程入门；

第六步：建立 20 条普通用户任务评估集。

十、结论

原项目和新项目共享同一套平台骨架、Java/Python 边界、FastAPI Runtime、SSE、Task/Trace 和 Docker 基础设施，平台层可大量复用。主要变化发生在产品定位、场景、Agent 角色、工具集、数据源、前端界面和评估指标上。新项目的技术难度整体高于原项目 M1，尤其是多 Agent 协作、文档理解、信息核查和主观评估；建议先做单 Agent MVP，再逐步升级为多 Agent 协作，避免一次性重写全部系统。
