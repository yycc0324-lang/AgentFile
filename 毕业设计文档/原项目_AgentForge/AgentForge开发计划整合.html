一、项目定位与目标

AgentForge 是一个 Agent 工作台：接入博客、Git 仓库、文档和爬虫内容，提供知识库问答、代码库问答、Coding Agent、内容生成和评估能力。原项目面向技术博主、研发团队和 Agent 学习者，目标是完整实践 Agent Runtime、RAG、Memory、Sandbox、Eval 和可观测性。

1.1 目标用户

个人技术博主：把博客、代码和爬取内容转成知识库，并生成文章、架构图和短视频脚本；

研发团队：做代码库问答、Issue 分析、自动修复和 PR Review；

Agent 学习者：完整实践 Agent Runtime、Memory、RAG、Sandbox、Eval、Observability。

1.2 非目标

不做模型训练和微调；

M1/M2 不做复杂多 Agent、K8s、插件市场；

不为了堆技术引入 Kafka、Flink、Service Mesh 等非必要组件。

5.2 Java -> Python

Java 调用 POST /agent/run，传入 task_id、project_id、conversation_id、message_id、query、show_citations、stream。Python 返回 NDJSON 事件流：route、step_start、tool_call、tool_result、step_end、answer、done。Java 将 route/step/tool_call/answer/usage 落库为 task_step、tool_call、trace_span、assistant message 和 token 字段。

5.3 数据接入 / 爬虫契约

Java 调用 POST /ingest/run，传入 project_id 和 sources（git / blog / url / crawl）。Python 返回 documents 与 chunks；Java 写 document/chunk，Python 写 Qdrant。

七、M1-M4 迭代路线

7.1 M1：最小可用 Agent（Repo + 博客 + 单 URL 接入）

目标：完成项目创建、Git/博客/手动上传/单 URL 接入、Router + ReAct + 4 个工具、SSE 对话、引用、完整 Trace 和 20 条评估集。

项目创建，填写 repo_url / blog_path；

数据接入：Git 仓库、博客目录、手动上传、单个 URL 抓取；

Router + ReAct + search_docs / search_code / read_file / list_files；

SSE 对话；回答带引用，支持 showCitations；

完整 Trace；20 条评估集，至少 16 条正确。

7.2 M2：长任务 Coding Agent（Issue -> 修改 -> 测试 -> PR）

目标：实现长任务 Coding Agent。

LangGraph 状态图；

Planner / Coder / Reviewer / Tester 多角色；

Memory 三层结构、Checkpoint / Resume、Completion Contract；

Docker Sandbox、GitHub MCP、代码库索引；

步骤级评估、OTel / Langfuse Trace。

7.3 M3：AgentOps 平台 + Content Agent

目标：平台化、评估体系、内容生产和部署。

Prompt 版本管理、模型网关、工具/MCP 注册中心；

数据集与评估 UI、评估回归 CI、合成测试集；

Content Agent：博客、架构图、短视频脚本；

Trace / Metrics Dashboard、权限与审批；

Docker / K8s 部署、多项目支持。

7.4 M4：生产化与平台运营（扩展）

M4 是生产化与规模化扩展，不属于原 M1-M3 核心范围。规划包括多租户、计费与配额、插件市场、高可用部署、跨区域部署、企业 SSO / SCIM、数据合规与脱敏，以及平台运营后台（租户管理、计费与用量、插件市场、部署管理、系统监控）。

十、验收标准

一条命令启动全部服务；

能从 Git 仓库、博客目录、单个 URL 接入数据；

能爬取 URL 并转 Markdown 入库；

Agent 能区分文档/代码问题；

至少 4 个工具可用；

每次执行有完整 Trace；

答案带引用，支持引用开关；

20 条评估集至少 16 条正确；

README 有架构图和启动说明。

十一、测试与部署

测试策略包括工具单元测试、Router 测试、API 集成测试、Task/Trace 落库测试和 20 条端到端评估集。部署使用 Docker Compose 启动 MySQL、Redis、Qdrant、MinIO、Java 和 Python；M3 再规划 K8s、监控和灰度发布。

十三、总结

本整合文档保留了原项目从 M1 到 M4 的完整开发计划、架构契约、数据模型、执行顺序和验收标准。原项目的核心资产是平台工程、Java/Python 双栈边界、Task/Trace 体系、RAG 管线和可扩展的 Agent Runtime，后续继续按 M1-M4 推进即可。
